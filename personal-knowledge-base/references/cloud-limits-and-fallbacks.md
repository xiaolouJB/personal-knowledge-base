# 云端版硬约束与降级对照（2026-10-04 资料库版更新）

这套方法在 Muse 托管环境里是全自动的；搬到 WorkBuddy 云端 + 原生资料库，约束比 ima 版少一条。执行和对外讲解时都必须如实分层，不许把降级能力说成全自动。

## 两条硬约束（ima 版的 2 条已解除或降级）

### 1. 个人微信直推不存在（不变）
WorkBuddy 官方推送出口只有 WorkBuddy 小程序和企业微信机器人；云端自动化通知走 App 系统通知。能在微信聊天里用的「微信助理」是远程控制一台常开的本地电脑，不是云端能力。
→ **降级说法**：复盘在 WorkBuddy App / 小程序里看，全文以资料库存档为准（附文档链接，点开即读，比 ima 版还省一步）。

### 2. 云端处理视频基本不成立（不变）
WorkBuddy 无官方音视频转写功能；资料库的 drive 通道不支持视频文件直接解析，也不支持 Bilibili / YouTube / 抖音视频链接直存。
→ **现实流程**：视频链接 → 先按 `references/retrieval-fallbacks.md` 第 3 级梯队找字幕轨或开源转写工具拿到文字稿 → 文字稿进归档流程 → 云端再做总结与复盘。没有文字稿就不处理、不编摘要。

## 已解除：云端存回知识库
ima 版的「云端回存 ima 官方未确认」在资料库版不再成立：资料库是 WorkBuddy 原生模块，云端沙箱经 auth-proxy 注入身份可直接读写（内置「资料库」skill 的 doc/manage 路由），回存是官方通道。
→ **仍保留的保险**：存完必须回读节点复查（这是 Skill 的铁律，与介质无关）；复查不到就把正文发在对话里让用户手动保存，并明说失败。以真机验证（library-setup.md 第 6 步）结果为准。

## 能力对照表

|---|---|---|
| 丢链接自动抓正文 | ✅ | ⚠️ 多数网页可抓；抓不到先走 retrieval-fallbacks.md 梯队（含 GitHub 开源工具实测），走完才标「正文待补」 |
| 图片读取整理 | ✅ | ✅（看不清处标注未取得） |
| 视频直接转写 | ✅（有转写管线） | ❌ 必须先在别处拿到文字稿 |
| 按模板成文 | ✅ | ✅ |
| 受控标签 | ✅ | ✅（词表存资料库《总索引与标签词表》文档） |
| 存回知识库 | ✅ 本地文件 | ✅ 原生通道，存后必须复查，失败发正文手动存 |
| 随感原话记录 | ✅ | ✅ |
| 定时复盘 | ✅ | ⚠️ 需隔夜验证定时唤醒是否可靠 |
| 复盘推送到个人微信 | ✅（聊天直达） | ❌ 只有 App / 小程序通知，但复盘有文档链接可点 |
| 全库索引维护 | ✅ | ✅（《总索引》文档自动更新，失败发对话） |

## 讲解口径（写教程、对外介绍时照此说）
- 能说的：「云端处理文章、存进 WorkBuddy 资料库、定时复盘」——但每句都要带上验证状态。
- 不能说的：「丢视频链接全自动入库」「复盘直推微信」——除非用户真机验证通过并更新本文件。
- 抓内容类的话要说全：「抓不到会先换入口、再找平台公开接口或 GitHub 开源工具实测，走完 3 条路线才标待补」，不夸大也不贬低。

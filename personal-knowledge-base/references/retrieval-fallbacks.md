# 内容获取失败时的升级梯队（先找办法，后标待补）

总规矩（用户亲口立的，2026-09-30 起、2026-10-04 扩展）：**遇到问题先自己想办法解决，不要第一次失败就回报「拿不到」。按「全网搜索解决方案 → 特别去 GitHub 找开源工具/现成实现 → 实测 → 再汇报」走完，一个平台最多认真试 3 条路线；实在没有方案，才标「待补」并说明试过什么、卡在哪、建议怎么办。没搜过 GitHub 之前，不许说做不到。**

找工具时的纪律：
- 先全网搜，再 GitHub 搜。GitHub 搜索词公式：`<平台名> + downloader / transcript / parser / scraper / 字幕 / 转文字`（中英各试一次），例如 `douyin transcript`、`bilibili subtitle downloader`、`x twitter replies scraper`。
- 选工具先看三样：最近更新时间（一年内优先）、Star 与使用人数、README 是否写清输入输出。来路不明、要交账号密码或 Cookie 的工具不用。
- 找到先拿当前这一条内容小样实测，跑通再用；跑不通换下一个，不要在一个工具上死磕超过两轮。
- 慢速、留间隔：同一平台连续请求触发风控/人机验证后会升级拦截（IP 级、可持续数小时）。宁可慢，不要连发；被拦就停，记下「待冷却后重试」，不许换着花样硬闯登录墙、付费墙。
- 第三方接口只是工具不是权威：用它拿到内容后，关键数据（作者、发布时间、互动数）能交叉核对的核对一次，笔记里注明实际获取路径。

## 梯队（按顺序试，成功即停）

### 第 1 级：常规入口
直接打开链接抓正文/字幕；短链先展开成真实链接；分清是主帖还是回复、是正文还是评论区。

### 第 2 级：换入口找同一内容
- 用搜索引擎搜「标题 / 作者 + 关键词」，找转载、聚合、第三方榜单/爆文库的元数据兜底
- 换平台的分享页、移动版页面、作者主页里的同一条内容
- 公众号/网页类：搜标题找原文镜像或作者其他渠道的同文

### 第 3 级：平台专用公开路线与开源工具（GitHub 优先）
下面是已实测过的路线（在 Muse 侧验证过；WorkBuddy 云端能否调用取决于其联网/工具能力，能调就调，调不了就把路线写进回报、建议用户在桌面端跑）：

- **X / Twitter 主帖**：FxTwitter 公开接口 `https://api.fxtwitter.com/<用户名>/status/<帖子ID>`（免登录，返回正文、作者、互动数据、媒体，X Article 长文全文也能拿到）；备选 `api.vxtwitter.com` 同形态。网页端打不开时先走这条，不要死磕 x.com。
- **X 回复**：Nitter 镜像页整页解析可得主帖 + 顶层回复（含作者自回复串），第 2 页要翻页 cursor，二级回复在各回复自己的 status 页下；镜像短时间连抓会触发人机验证，必须慢速。此法源自 GitHub 开源工具 x2md 的思路——同类问题先去 GitHub 找有没有人已经趟过。
- **YouTube / Bilibili 视频**：先找官方字幕轨（yt-dlp 一类开源工具可拉字幕）；没字幕轨再考虑转写工具。资料库不支持 Bilibili / YouTube 视频链接直存，这条只解决「拿到文字稿」，文字稿再进归档流程。
- **抖音 / 小红书 / 快手等短视频**：先试分享链接展开 + 平台网页版 + 搜索引擎里的标题/作者/文案转载；再去 GitHub 搜该平台的解析/字幕提取开源工具实测。实在只拿到画面信息时，笔记按「视频口播未取得」标注，只整理能确认的元数据和画面文字，并写清缺口。
- **微信公众号**：正文直抓失败时，搜标题找转载与引用；只拿到摘要就只写摘要并标待补，不许补全正文情节。

### 第 4 级：诚实收尾
3 条路线都试过仍拿不到，才允许这样收尾：
1. 笔记照常建，状态标「正文待补」，只写已确认的标题、作者、链接、已知元数据
2. 在笔记末尾加一节「获取记录」：试了哪几条路线、各卡在哪一步、下次可重试的条件（如冷却后、用户补截图/文字稿）
3. 回报用户时说清：试过什么、为什么失败、你的建议是什么（例如「你顺手截个图发我，我按图归档」）——给建议，不把选择题原样抛回去

## 截图兜底（给用户的默认建议话术）
反复抓不到的平台（典型是 X 和短视频），建议用户养成「链接 + 截图」一起丢的习惯：正文抓不到时，截图就是最可靠的正文来源，按图片流程归档并注明「正文据用户截图」。

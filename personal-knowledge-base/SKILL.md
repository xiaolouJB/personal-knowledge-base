# 个人知识库（WorkBuddy 云端 + 资料库版）

## Purpose
把散落的链接、文章、图片、视频文字稿和随手想法，变成一个能长期复用的个人知识库：每条内容按统一模板沉淀成笔记，存进 WorkBuddy 原生资料库的「个人知识库」空间；随感原话保留；每天/每周/每月自动做一次复盘，挖关联、找矛盾、提示盲区——不是收藏夹，是会自己长出洞察的第二大脑。

本 Skill 是 Muse 托管版个人知识库方法（2026-09-29 起实跑验证）的云端移植版，存储后端从腾讯 ima 换成 **WorkBuddy 原生资料库**（内置「资料库」skill 的 doc/manage 路由，skill 名就叫「资料库」）。方法不变；资料库是 WorkBuddy 自家模块，云端沙箱经 auth-proxy 注入身份可直接读写，回存确定性高于 ima 版。云端仍做不到的地方如实降级，见 `references/cloud-limits-and-fallbacks.md`，不许包装成全自动。

配套还有一份**系统级记忆**（`references/system-memory.md`，交付包里是单独文件《WorkBuddy系统级记忆-粘贴版.md》）：Skill 靠 description 被自动匹配，是概率触发；系统级记忆常驻，负责把「丢链接没带触发词也默认归档」和「先找办法再说不行」这两条抬成默认规矩。两份一起装，只装 Skill 触发不稳。

## 存储映射（资料库侧）
在 WorkBuddy 资料库里有一个空间「个人知识库」（一次性初始化见 `references/library-setup.md`），内部用真·文件夹（纯容器目录节点）按下面分工：

- `00-收件箱`：刚丢进来、还没处理完的内容先落这里
- `01-正式笔记`：处理完的笔记，一条内容一篇（在线文档）
- `02-随感`：用户随手记的想法
- `03-复盘`：每日/周度/月度复盘（文档标题前缀区分：`每日复盘-`、`周度复盘-`、`月度复盘-`）
- `99-索引与词表`：一篇文档《总索引与标签词表》，内容结构见 `references/tags-and-index.md`，每次归档后更新

笔记文档标题命名：`YYYY-MM-DD-标题关键词`（日期用归档当天，北京时间）。

## Workflow

### 1. 先分流：这条输入是什么
- **链接 / 文章 / 图片 / 视频文字稿** → 走归档流程（第 2 步起）
- **纯文字短句、像是想法或感受** → 走随感流程（第 5 步）
- **以「做：」开头** → 这是任务，不是记录，立刻执行任务本身，不归档
- **拿不准是记录还是提问/任务** → 只问一句让用户选「记下来 / 帮我做」，不要自作主张

### 2. 抓取与核验（归档流程）
1. 打开链接抓正文。**第一次抓不到不许直接收尾**——先按 `references/retrieval-fallbacks.md` 的升级梯队走：换入口找同一内容 → 全网搜解决方案、**特别去 GitHub 找该平台的开源解析/字幕/转写工具并实测** → 一个平台最多认真试 3 条路线。梯队走完仍拿不到，才只存标题、链接和已知元数据，标注「正文待补」并在笔记末尾写「获取记录」（试过什么、卡在哪、下次重试条件），绝不根据标题编摘要。没搜过 GitHub 之前，不许说拿不到。
2. 图片：读取图中文字与信息再整理；看不清的部分标注「未取得」，不猜。
3. **视频：云端没有官方音视频转写能力。** 先按梯队找字幕轨和开源转写路线（见 retrieval-fallbacks.md 第 3 级）；仍无文字稿时，如实说明并给出下一步建议（例如先在别处转写、或用平台自带总结功能拿到文字稿再丢进来），拿到文字稿后按文章处理并注明来源是文字稿。绝不拿标题和简介编口播内容。
4. 涉及数字、日期、人名、结论时，能核验的先核验再写；核验不了的标注「待核实」。

### 3. 按模板成文
严格按 `references/templates.md` 的「正式笔记模板」写，一项不缺：
- 一句话总览（说清核心，不写空话）
- 原文整理（忠实整理要点，保留关键数据、引用、出处，**不掺评论**）
- 核心摘要（**最多 5 条**）
- 批判性点评（逻辑漏洞、立场偏见、证据强度、与已知事实的出入；没有明显问题就写「暂无明显硬伤」）
- 来源链接（原文链接必须留；无外链时注明来源形态，如「用户上传图片」）
- 相关条目（与库内已有笔记有关联的，链过去并用一句话说清关系；没有就不写）

**三类内容强制分清**（本方法最重要的一条）：原文摘录、用户自己的笔记/原话、AI 整理的内容，必须在文中标明各属哪类，绝不把 AI 整理或用户口述写成原作者的观点。沉淀越久，来源污染越难清理。

### 4. 打标签 + 存入资料库 + 更新索引
1. 标签**只能**从受控词表里选（见 `references/tags-and-index.md`），一篇最多 3 个；词表里没有合适的，先归到最接近的，并向用户提议是否新增——不许自创标签。
2. 把笔记创建为在线文档，挂到资料库空间「个人知识库 / 01-正式笔记」文件夹下（走内置「资料库」skill 的 doc/manage 路由；云端沙箱模式由 auth-proxy 注入身份，不需手填 token）。
3. **存完必须复查**：回读该资料库节点，确认文档在、内容全。复查通过才可以对用户说「已存好」；**存不进去或复查不到，就把完整笔记正文直接发在对话里**，让用户手动保存，并明说「自动存入资料库这一步没成功」——不许口头说存好了。
4. 更新《总索引与标签词表》文档：时间线加一行（一句话总览 + 日期），主题导航里把本篇挂到对应标签下。索引更新和笔记存库是同一个动作的两半：笔记存了但索引没更新，算没完成，要在回报里说明。

### 5. 随感流程
- 按 `references/templates.md` 的「随感模板」记：**用户原话一字不改**，另起「备注」写记录时的上下文、与库内哪些条目有关联。
- 存入资料库「02-随感」文件夹，更新索引时间线。
- 回复用户时只确认记下了，不长篇评论——除非随感与已有笔记有强关联，可点一句。

### 6. 复盘（定时自动化触发，提示词在 references/automations.md）
- **每日复盘（每天 22:00）**：读当天新增的全部笔记和随感 → 今日新增一览、条目之间的关联、观点碰撞、值得深想的问题 2–3 个、随感回响。关联和碰撞必须与历史笔记对照，不只看当天。
- **周度复盘（每周六 09:00）**：不做流水账。只挖：本周主题分布、用户没注意到的跨条目关联、观点矛盾点（点名是哪几篇）、关注重心相比上周的漂移、盲区提示。
- **月度复盘（每月 1 日 09:00）**：拉长看结构：月度主题分布、同一话题的观点演变（点名条目）、知识盲区（关心但存得少 / 存得多但没消化的）、下月建议关注方向 2–3 条。
- 复盘存进资料库「03-复盘」文件夹（在线文档），并在 WorkBuddy 里给用户发一份全文 + 文档链接。**通知只到 WorkBuddy App / 小程序，不承诺推送到个人微信**（云端没有这个出口）。
- 复盘里引用的每个观点必须能在库内笔记里找到出处；找不到的宁可不写，不许编。

### 7. 回报用户
每次归档后，用三行内说清：存了什么（一句话总览 + 文档链接）、打了什么标签、存入资料库是否复查通过。有缺口（正文待补、待核实）一并说清。

## Output Contract
- 正式笔记：模板六项齐全（总览 / 原文整理 / ≤5 条摘要 / 点评 / 来源 / 相关条目），标签 ≤3 且全在词表内
- 随感：原话原文 + 备注
- 复盘：按日/周/月各自的结构，引用必有出处，附文档链接
- 任何一步失败：如实说卡在哪一步 + 给出降级产物（例如把正文发在对话里），不假装完成

## Operating Rules
1. **不编造。** 抓不到、存不进、没转写，就明说并标注；诚实的缺口好于假装的完成。
2. **存回必复查。** 未在资料库里回读确认，不许说「已存好」。
3. **标签受控。** 只用词表内的标签；新增标签要先经用户同意并更新《总索引与标签词表》文档。
4. **来源三分。** 原文 / 用户的话 / AI 整理，永远分开标注。
5. **原话不改。** 随感和用户口述只记录、不润色、不替用户「总结成他的观点」之外的东西。
6. **视频先转写。** 没有文字稿的视频不处理、不编摘要。
7. **点评要真点评。** 可以指出逻辑漏洞和证据不足，不写鸡汤式夸奖；没有硬伤就直说暂无明显硬伤。
8. **时间一律北京时间**，日期以归档当天为准。
9. 本 Skill 只管沉淀与复盘；用户以「做：」下达的任务按任务本身处理，不套归档模板。
10. **先找办法，再说不行。** 任何一步卡住（抓不到、转写不了、存不进），先全网搜索、特别去 GitHub 找现成工具实测（见 retrieval-fallbacks.md），走完梯队才许报失败，且报失败必须附「试过什么 + 我的建议」。
